## 2. 測試階段（最多 5 題）

```
步驟 1：單題測試（1 題）
        ↓ 成功才繼續
步驟 2：確認回應格式正確（JSON 可解析）
        ↓ 正確才繼續
步驟 3：小批次測試（3-5 題）
        ↓ 成功才繼續
步驟 4：回報案主確認品質
        ↓ 案主同意才繼續
步驟 5：開始批次生成
```

**測試總量不超過 5 次 API 請求**（Free Tier 配額珍貴）

---

## 3. 錯誤處理策略

| 錯誤代碼 | 意思 | 處理方式 |
|----------|------|----------|
| **429** | 配額超限 | **立即停止**，回報案主，等待隔天配額重置 |
| **503** | 伺服器忙 | 暫停 60 秒，最多重試 1 次 |
| **JSON 錯誤** | 回應格式錯 | 記錄錯誤，跳過該題，繼續下一題 |
| **網路錯誤** | 連線問題 | 等待 10 秒，重試 1 次 |

### 重要原則

- **重試上限：1 次**（不是 3 次！）
- **遇到 429 必須立即停止**，不可重試
- 區分「可重試的錯誤」vs「必須停止的錯誤」

## 4. 批次執行參數

| 參數 | 建議值 | 說明 |
|------|--------|------|
| 每題間隔 | **5 秒** | 避免觸發 Rate Limit |
| 每批數量 | **依配額調整** | Free Tier: 最多 16 題/天 |
| 每日上限 | **配額的 80%** | 預留緩衝空間 |
| 重試次數 | **1 次** | 避免浪費配額 |

### 時間估算

| API Key 類型 | 每日可處理 | 14,000 題需時 |
|--------------|-----------|---------------|
| Free Tier (20/天) | 16 題 | **875 天（不可行）** |
| 付費版（假設 1,000/天） | 800 題 | ~18 天 |
| 付費版（假設 10,000/天） | 8,000 題 | ~2 天 |

## 5. 進度管理

```
執行腳本
    ↓
每 10 題儲存進度（checkpoint）
    ↓
每 100 題輸出統計報告
    ↓
遇到 429 → 立即停止 → 儲存進度 → 回報案主
    ↓
隔天從 checkpoint 繼續
```

### 進度檔案

- 進度記錄：`scripts/.quiz-options-progress.json`
- 輸出結果：`src/data/quiz-options.json`

## 6. 變更控制

**任何變更必須先詢問案主**：

| 變更類型 | 範例 | 處理方式 |
|----------|------|----------|
| 模型變更 | gemini-2.5 → gemini-3 | **可討論，不可擅自修改** |
| 參數調整 | 間隔時間、重試次數 | 必須詢問 |
| 批次大小 | 50 → 100 題 | 必須詢問 |
| Prompt 修改 | 任何 prompt 變更 | 必須詢問 |

### 模型變更流程

```
發現問題或有建議
    ↓
向案主提出討論（說明原因、比較利弊）
    ↓
案主同意後才可變更
    ↓
更新 SOP 文件記錄
```

### 禁止事項

- ❌ 禁止擅自更換模型（必須先討論取得同意）
- ❌ 禁止擅自調整配額使用策略
- ❌ 禁止在未確認前執行大量請求
- ❌ 禁止設定重試次數超過 1 次

## 7. 執行前檢查清單

每次執行腳本前，確認以下項目：

```
□ 確認使用正確模型（gemini-3-flash-preview）
□ 確認 API Key 類型（Free Tier 或付費）
□ 確認當日剩餘配額
□ 先跑 1 題測試，確認 API 可用
□ 確認回應格式正確（JSON 可解析）
□ 案主同意後才開始批次
□ 確認錯誤處理：429 = 立即停止
□ 確認重試次數 = 1（不是 3）
□ 確認進度儲存機制正常
```

## 11. 歷史教訓（2026-02-11）

### 問題事件

| 問題 | 原因 | 後果 |
|------|------|------|
| 使用錯誤模型 | Claude 擅自改用 `gemini-2.5-flash` | 違反案主決策 |
| 配額快速耗盡 | 重試次數設為 3 次 | 20 次配額只完成 1 題 |
| 錯誤估算 | 以為 Free Tier 有 1,500/天 | 實際只有 20/天 |

### 根本原因

```
腳本設定：MAX_RETRIES = 3
每題失敗重試 3 次 = 4 次請求/題
前 5 題全部失敗 = 20 次請求
→ Free Tier 配額用完
→ 只成功 0-1 題
```

### 預防措施

1. **模型不可擅自更換**：已經過測試比較
2. **重試次數 = 1**：避免浪費配額
3. **確認 API Key 類型**：Free Tier 不適合批次生成
4. **先單題測試**：確認可用才繼續
